i. Casual Description

The use cases below cover every system requirement from Report One, Part One. Each one lists the requirements it responds to. UC-1 to UC-10 are started by the Citizen / User. UC-11 is started by the system's own scheduler. It keeps the stored government information current by crawling official ministry websites, Facebook pages, and Telegram channels.

Use CaseNameCasual DescriptionRequirements
UC-1AskQuestionThe user types a question about a Cambodian government service in Khmer, English, or a mix of both, and submits it. SuperAsk.AI finds the relevant official information and returns an answer. Where the source has them, the answer lists the procedure steps in order, the required documents, fees and late fees, deadlines or validity periods, and office hours.REQ-1, REQ-2, REQ-3, REQ-5, REQ-16, REQ-17, REQ-18, REQ-19, REQ-20, REQ-31, REQ-32, REQ-33
UC-2RetrieveOfficialSourcesThe system searches its stored official government content for the passages most relevant to the question and passes only those to the AI Model Service. It is always included in UC-1.REQ-4, REQ-5, REQ-8
UC-3ViewSourceCitationThe user sees the official source behind the answer: the ministry, the document or page, a link, the effective date, and the last-verified date. The citation is kept visually separate from the answer text. It is always included when a sourced answer is shown.REQ-6, REQ-28, REQ-34
UC-4DeclineUnsupportedQuestionIf no verified official source covers the question, or the question is out of scope, the system says it cannot answer. It does not guess. It tells the user which areas it does cover so they can rephrase. This extends UC-1.REQ-7
UC-5BrowsePopularProceduresThe user picks a common procedure, such as passport application or birth certificate, from the sidebar or the welcome screen. The system sends it as a question and answers it as in UC-1.REQ-9, REQ-35
UC-6ViewRecentConversationsThe user opens the list of recent questions and conversations and selects one to go back to a topic they viewed earlier.REQ-10, REQ-36
UC-7GetOfficeContactAndLocationThe user asks for the contact details and location of the ministry or office that handles their procedure. The system shows the phone number, address, office hours, and a map link. If there is no online contact, it says so and shows the office location instead.REQ-11, REQ-12, REQ-13, REQ-20, REQ-38, REQ-39
UC-8AskFollowUpQuestionAfter receiving an answer, the user asks a follow-up question, such as "how much does it cost?". The system uses the earlier conversation to work out what "it" refers to. This extends UC-1.REQ-14
UC-9AskThroughMessagingChannelThe user sends a question to SuperAsk.AI through Telegram or Messenger instead of the website. The platform forwards it, the system answers it through UC-1, and the platform sends back the answer with its source.REQ-15
UC-10SwitchLanguageThe user switches the interface between Khmer and English. Answers come back in the language the question was asked in.REQ-2, REQ-37
UC-11RefreshOfficialContentOn a schedule, the system crawls the registered official sources: ministry websites, Facebook pages, and Telegram channels. It saves new or changed content with its source link and fetch date, and updates the stored information and its last-verified date. New ministries are added by registering their sources, without changing the answer-generation logic.REQ-4, REQ-8, REQ-29, REQ-30

ii. Use Case Diagram

AskQuestion (UC-1) is the central use case. It always <<include>>s RetrieveOfficialSources (UC-2) and ViewSourceCitation (UC-3), because every answer is looked up and cited. BrowsePopularProcedures (UC-5) and AskThroughMessagingChannel (UC-9) both <<include>> AskQuestion, since they are different ways of asking the same question. AskFollowUpQuestion (UC-8) and DeclineUnsupportedQuestion (UC-4) <<extend>> AskQuestion, because they only happen in some conversations. RefreshOfficialContent (UC-11) runs on a schedule and collects content from the official websites, Facebook pages, and Telegram channels.

iv. Fully-Dressed Description

The five use cases below have the highest priority weights, based on the requirement weights from Report One, Part One. They are also the core of the first demonstration. In each flow, → marks an action by an actor and ← marks the system's response.

Use Case UC-1: AskQuestion
Related RequirementsREQ-1, REQ-2, REQ-3, REQ-5, REQ-16, REQ-17, REQ-18, REQ-19, REQ-20, REQ-31, REQ-32, REQ-33
Initiating ActorCitizen / User
Actor's GoalTo get accurate information about a government procedure (steps, required documents, fees, deadlines, office hours) in Khmer or English.
Participating ActorsAI Model Service
PreconditionsThe SuperAsk.AI web interface is open. The stored official content has been loaded (UC-11 has run at least once).
PostconditionsThe user has an answer supported by a displayed official source, or a clear statement that no verified source is available (UC-4). The question and answer appear in the recent conversations list.
Flow of Events for Main Success Scenario → 1. User types a question in Khmer, English, or a mix of both into the chat input field.
→ 2. User submits the question by pressing Enter or the send button.
← 3. System shows the question in the conversation and a loading indicator.
← 4. System detects the question's language and normalises the Khmer text.
← 5. System checks that the question is about a government service and not an out-of-scope request.
← 6. include:: RetrieveOfficialSources (UC-2).
← 7. System sends the question and the retrieved passages to the AI Model Service, which writes an answer using only those passages.
← 8. System checks that every fee, date, and document in the answer appears in a cited source.
← 9. System shows the answer in the question's language. Where available, it lists the steps in order, the required documents, fees and late fees, deadlines, and office hours.
← 10. include:: ViewSourceCitation (UC-3).
← 11. System adds the question to the recent conversations list.
Flow of Events for Extensions (Alternate Scenarios) 2a. User submits an empty input.
← 1. System ignores the submission and keeps the send button disabled.

5a. The question is not about a government service (for example, general knowledge or translation).
← 1. System tells the user that SuperAsk.AI only answers questions about Cambodian government services, and makes no retrieval or model call.

6a. No passage relevant enough to the question is found.
← 1. extend:: DeclineUnsupportedQuestion (UC-4).

7a. The AI Model Service is unavailable or times out.
← 1. System falls back to showing the most relevant retrieved passage word for word, with its citation.

8a. The answer contains a claim that no cited source supports.
← 1. System withholds the answer and tells the user it could not confirm every detail against an official source.

9a. The user asks a follow-up question about the answer.
→ 1. extend:: AskFollowUpQuestion (UC-8).

Use Case UC-2: RetrieveOfficialSources
Related RequirementsREQ-4, REQ-5, REQ-8
Initiating ActorIncluded by UC-1 AskQuestion (on behalf of Citizen / User)
Actor's GoalTo find the official passages that answer the question, so that the answer is based only on them.
Participating ActorsNone (uses the system's stored official content)
PreconditionsA question has been submitted and passed the scope check. The content store contains official content collected by UC-11.
PostconditionsA ranked list of relevant passages is returned, each with its source metadata, or an empty result that triggers UC-4.
Flow of Events for Main Success Scenario ← 1. System splits the Khmer or English question into search terms and adds known synonyms and abbreviations (for example, "MPWT" and "Ministry of Public Works and Transport").
← 2. System runs a keyword search and a meaning-based search over the stored content.
← 3. System merges and re-ranks the two result lists.
← 4. System removes outdated or replaced content, keeping only content that is currently in effect.
← 5. System checks that the top result scores above the minimum relevance threshold.
← 6. System returns the top passages, each with its ministry, source link, effective date, and last-verified date.
Flow of Events for Extensions (Alternate Scenarios) 2a. The question is a follow-up that does not name its subject (for example, "how much is it?").
← 1. System rewrites the question using the earlier conversation before searching.

5a. No result reaches the minimum relevance threshold.
← 1. System returns an empty result, and the calling use case continues with DeclineUnsupportedQuestion (UC-4).

5b. The top result is related but does not mention most of what was asked.
← 1. System marks the result as low confidence, so the answer is shown with a note that the source may not fully answer the question.

Use Case UC-3: ViewSourceCitation
Related RequirementsREQ-6, REQ-28, REQ-34
Initiating ActorCitizen / User
Actor's GoalTo confirm where the answer came from and how current it is.
Participating ActorsNone
PreconditionsA sourced answer has been shown (UC-1).
PostconditionsThe user has seen the source details and, if they chose to, opened the official source.
Flow of Events for Main Success Scenario ← 1. System shows a "Verified Source" card under the answer, visually separate from the answer text.
← 2. System shows the ministry, document or page title, effective date, and last-verified date on the card.
→ 3. User reads the source details.
→ 4. User selects the link icon on the card.
← 5. System opens the official source page (ministry website, Facebook post, or Telegram post) in a new tab.
Flow of Events for Extensions (Alternate Scenarios) 2a. The source's last-verified date is past its review date.
← 1. System marks the citation as possibly outdated and adds a note asking the user to confirm with the office before acting.

2b. The answer is supported by more than one source.
← 1. System shows one card per source, in the order they are cited.

3a. User finds the information incorrect.
→ 1. User selects "Report" on the answer and optionally adds a comment.
← 2. System records the report against the cited source for review.

Use Case UC-4: DeclineUnsupportedQuestion
Related RequirementsREQ-7 (also supports REQ-23)
Initiating ActorExtends UC-1 AskQuestion (on behalf of Citizen / User)
Actor's GoalTo be told honestly when SuperAsk.AI has no verified answer, instead of getting a guess.
Participating ActorsNone
PreconditionsRetrieveOfficialSources (UC-2) found no relevant official source, or the question is outside what SuperAsk.AI is allowed to answer (for example, legal advice or a personal case).
PostconditionsNo unsupported answer has been shown. The user knows what SuperAsk.AI does cover.
Flow of Events for Main Success Scenario ← 1. System stops before generating an answer.
← 2. System tells the user, in the question's language, that it has no verified official source for this question and will not guess.
← 3. System lists the ministries and service areas it currently covers.
→ 4. User rephrases the question or picks a covered procedure, and UC-1 starts again.
Flow of Events for Extensions (Alternate Scenarios) 1a. The question asks for something SuperAsk.AI must not give (legal advice, a personal case lookup, a prediction of an official decision, or a tax calculation).
← 1. System explains why it cannot answer this kind of question and points the user to the responsible authority.

1b. The question describes an emergency.
← 1. System shows emergency phone numbers immediately and ends the flow.

4a. User ends the conversation.
→ 1. User closes the chat or starts a new conversation.

Use Case UC-7: GetOfficeContactAndLocation
Related RequirementsREQ-11, REQ-12, REQ-13, REQ-20, REQ-38, REQ-39
Initiating ActorCitizen / User
Actor's GoalTo know how to contact the responsible ministry or office and where to go in person.
Participating ActorsNone (uses the stored office information)
PreconditionsThe web interface is open. Contact and location details for the office have been collected from its official website, Facebook page, or Telegram channel (UC-11).
PostconditionsThe user has the office's contact details and location, or a clear statement that no online contact is available together with the office location.
Flow of Events for Main Success Scenario → 1. User asks for the contact and location of the office responsible for a procedure (for example, "can I have the contact and location of the ministry for this?").
← 2. System works out which procedure "this" refers to from the conversation (UC-8).
← 3. System finds the ministry or office responsible for that procedure.
← 4. System shows a contact card with the office name, address, office hours, phone number, and an "Open in Google Maps" link.
← 5. System shows the official source the contact details came from.
→ 6. User selects "Open in Google Maps".
← 7. System opens the office location in Google Maps in a new tab.
Flow of Events for Extensions (Alternate Scenarios) 4a. No online contact information is available for the office.
← 1. System states "No verified online contact information is available."
← 2. System shows the office location and the Google Maps link instead.

4b. Neither contact nor location information is available from an official source.
← 1. System says it has no verified contact or location for this office and does not guess one.

3a. The procedure is handled by several offices (for example, a provincial office and the ministry in Phnom Penh).
← 1. System asks the user which province they are in.
→ 2. User answers, and the flow continues at step 4 with the matching office.

1a. User asks without naming or having discussed a procedure.
← 1. System asks which procedure or ministry the user needs.
→ 2. User names it, and the flow continues at step 3.
