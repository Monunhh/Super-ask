5. Items that do not apply and archive layout

Code, unit tests and data collection scripts stay at the repository root

The folders 1_code, 2_unit_testing and 4_data_collection in the e-archive hold a README each (README1, README2, README4) instead of a copy of the files. SuperAsk is a Next.js application, and Next.js requires its source folders (app/, components/, lib/) at the repository root. The unit tests in tests/ and the data collection scripts in scripts/ and data/registry/ import that code and read and write data/ by path, so they must stay there too. A copy in the e-archive would be a second version that goes out of date. Each README gives the exact location and the commands to run the code. The integration tests have their own configuration and are kept in 3_integration_testing.

Nothing is missing, so we do not propose moving any points away from items 1, 2 and 9.

Item 8, database design, does not apply

SuperAsk has no database in Phase 0. The knowledge base, curated answers, glossary, office directory and source registry are version-controlled JSON files in data/, so every change to official content is reviewed and recorded in git. Audit and feedback records are append-only log files. We propose moving the points for item 8 to item 9, data collection, which covers the design of those data files and the registry of 132 government websites.
